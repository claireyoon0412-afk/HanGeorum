# 서울 신호 횡단보도 접근성 점검 대시보드

2026 데이터분석 연구발표회 · 팀 한걸음 (20913 윤혜정)

## 주제

서울 신호 횡단보도의 접근성을 점검하고 우선 개선 지점을 찾는다. 시각장애인을 중심으로, 노인·휠체어 이용자·유아차 동반 보행자 등 보행이 불편한 모든 이용자를 대상으로 한다. (음향신호기·점자블록 : 시각장애인, 보도턱낮춤 : 휠체어·보행보조기·유아차 이용자, 녹색신호시간 : 노인·장애인 등 걸음이 느린 보행자)

큰 질문 : 서울의 신호 횡단보도는 시각장애인과 걸음이 느린 보행자가 혼자 안전하게 건널 수 있는 조건을 얼마나 갖추고 있으며, 어느 지점을 우선적으로 개선해야 하는가?

## 데이터를 열어 보고 알게 된 것

전국횡단보도표준데이터(데이터기준일자 2026-08-26)에서 서울특별시 행은 **동작구 1,057곳뿐**이었다. 서울 25개 자치구 가운데 음향신호기·점자블록·보도턱낮춤 기록을 공공데이터로 공개한 곳은 동작구 1곳이다. 그래서 분석을 두 층으로 나눴다.

| 화면 | 범위 | 질문 |
|---|---|---|
| 분석 · 서울 기록 현황 | 서울 전체 (서울시 자료) | 보행등이 있는 횡단보도 가운데 시설 기록을 확인할 수 있는 곳은 얼마인가? |
| 분석 · 음향신호기 설치율 | 동작구, 법정동별 | 동마다 음향신호기 설치율은 얼마나 다른가? |
| 분석 · 녹색신호시간 | 동작구 | 보행약자 기준(7초 + 길이 ÷ 0.8)보다 짧은 곳은 몇 %이고, 몇 초가 부족한가? |
| 분석 · 시설 종합과 우선 개선 | 동작구 | 세 시설을 모두 갖춘 곳은 몇 %이고, 결손이 많은 곳은 어디인가? |
| 자료 · 데이터 점검 | 동작구 | 전처리 기록, 시설 항목의 세 상태, 두 자료 대조 |

### 체험 기능

| 화면 | 내용 |
|---|---|
| A. 현장 로드뷰 점검 | 결손 횡단보도를 지도에서 고르고 카카오맵 로드뷰로 실제 거리 모습을 확인한다. 현장 점검 결과(보임/보이지 않음)를 기록해 CSV로 내려받는다. `.streamlit/secrets.toml`에 `KAKAO_JS_KEY`를 넣으면 로드뷰가 앱 안에 바로 표시된다. 로드뷰 사진은 분석에 쓰지 않는다. |
| B. 횡단 체험 | 실제 횡단보도의 길이·녹색신호시간으로 건너는 과정을 3인칭(위에서 보기) 또는 1인칭(직접 건너기)으로 재현한다. 보행속도, 시야(정상·저시력·전맹), 출발 방식, 음향신호기 유무를 바꿔 볼 수 있으며, 음향신호기가 있으면 녹색 신호 동안 안내음이 난다. |
| C. 내 주변 반경 점검 | 동작구 교차로(서울시 자료의 교차로명)를 고르거나 지도에서 횡단보도를 누르면, 반경 안 신호 횡단보도의 상태와 안전 등급(A~D, 이 앱이 정한 기준)을 보여 준다. |
| D. 개선 시나리오와 공개 요청서 | 우선순위대로 음향신호기를 추가 설치하거나 녹색신호시간을 연장했을 때 지표 변화를 계산하고, 그 결과를 담은 자치구별 요청서를 만들어 내려받는다. 기록이 없는 자치구는 기록 공개 요청서가 만들어진다. |
| E. 접근성 모드(사이드바) | 고대비·큰 글씨 화면, 모든 페이지의 글을 읽어 주는 음성 안내(그래프는 요약 문장으로 안내, 시뮬레이터 제외) |

## 전처리 원칙 : '없음'과 '모름'을 섞지 않는다

1. 시설 칸을 세 상태로 나눈다.
   - 설치(Y)
   - 미설치(N) = 없음 : 결손개수(0~3)에 센다.
   - 정보 없음 = 모름 : 빈칸, 알아볼 수 없는 값, 또는 자치구가 기록을 올리지 않은 경우. 결손으로 세지 않는다.
2. 기록이 없는 24개 자치구를 설치율 0%로 계산하지 않는다. 시설 지표는 기록을 공개한 동작구 안에서만 계산하고, 나머지는 '기록 없음'으로 따로 보여 준다.
3. 설치율 = 설치 ÷ (설치 + 미설치) × 100.
4. 횡단보도 시설 상태는 완비 / 결손 1·2·3개 확인 / 판단 보류(미설치는 없지만 정보 없음이 있음)로 나눈다.
5. 보행자신호등이 있는 횡단보도만 분석한다(동작구 324곳).
6. 녹색신호시간·횡단보도연장이 비어 있으면 '정보 없음'(14곳), 0 이하이거나 비정상적으로 크면 '이상값'으로 신호시간 분석에서만 뺀다.
7. 신호 횡단보도가 10곳 미만인 동은 비율이 크게 흔들리므로 순위 해석에서 뺀다.
8. 서울시 자료의 X·Y 좌표는 EPSG:5186(중부원점 TM)으로 보고 위도·경도로 바꿨다. 두 자료에 함께 있는 횡단보도관리번호로 위치를 대조해 확인했다(거리 중앙값 약 27m).

## 새로 만든 열

동(지번주소의 법정동), 기준녹색시간 = 7 + 횡단보도연장 ÷ 보행속도, 부족시간, 기준미달, 설치수, 미설치수(=결손개수), 정보없음수, 시설상태, 차로수구간

## 기능

- 사이드바 : [분석] [체험] [자료] 탭과 화면 선택(분석 5개, 체험 4개, 자료 1개), 법정동(여러 개), 보행속도 기준(1m당 1초 / 0.8m당 1초 / 0.7m당 1초), 결손개수 최소값, 정보 없음 포함 여부, 고대비·큰 글씨, 음성 안내
- 우선 개선 목록 CSV, 화면낭독기용 텍스트 목록, 현장 점검 기록 CSV, 요청서 TXT 내려받기

## 한계

시설 대장 기록이라 실제 작동 여부와 설치 품질을 알 수 없다. 서울에서는 동작구 기록만 있어 자치구 간 시설 비교는 할 수 없다. 녹색신호시간에 점멸 시간이 포함되는지에 따라 기준 미달 비율이 달라진다. 자치구별 시각장애인 수 자료를 구하지 못해 수요 대비 설치 수준은 비교하지 못한다.

## 생성형 AI 활용

전처리 코드와 웹앱 코드 초안은 Claude(Anthropic)로 작성했다. 연구 질문, 분석 대상 정의, 빈칸 처리 원칙, 보행속도 기준, 우선순위 기준, 결과 해석은 직접 판단했다. 핵심 숫자는 원본 CSV를 스프레드시트 필터로 열어 직접 세고 웹앱 값과 대조했다.
